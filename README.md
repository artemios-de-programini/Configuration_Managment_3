# Практическая работа №3: Ассемблер и интерпретатор УВМ (Вариант №8)

CLI-ассемблер и интерпретатор учебной виртуальной машины (УВМ) с
раздельной памятью команд и данных. Исходная программа записывается в
формате **CSV**, машинный код хранится в двоичном файле
(`little-endian`), дамп памяти — в формате **XML**. Проект реализован на
**Python 3** и использует только стандартную библиотеку.

- ассемблер (`src/main.py`): CSV → промежуточное представление →
  машинный код;
- интерпретатор (`src/interpreter.py`): машинный код → выполнение →
  XML-дамп памяти.

## Требования

- Python 3.10 или новее;
- установка сторонних пакетов не требуется.

## Спецификация УВМ (Вариант №8)

Все многобайтовые команды упаковываются в порядке **little-endian**:
младший байт идёт первым, биты нумеруются от 0 — младшего бита первого
байта. Поле `A` (биты 0–3) хранит код операции, остальные поля
располагаются друг за другом без пропусков.

### Загрузка константы (`load`), `A = 0`, 4 байта

- `B` (биты 4–17, 14 бит) — адрес назначения, диапазон `0..16383`;
- `C` (биты 18–30, 13 бит) — константа, диапазон `0..8191`;
- семантика: `data_mem[B] = C`;
- бит 31 всегда равен нулю.

### Чтение значения из памяти (`read`), `A = 1`, 5 байт

- `B` (биты 4–17, 14 бит) — адрес ячейки с базовым указателем;
- `C` (биты 18–31, 14 бит) — адрес результата;
- `D` (биты 32–39, 8 бит) — смещение, диапазон `0..255`;
- семантика: `addr = data_mem[B] + D`, затем
  `data_mem[C] = data_mem[addr]`.

### Запись значения в память (`write`), `A = 9`, 5 байт

- `B` (биты 4–17, 14 бит) — адрес источника;
- `C` (биты 18–31, 14 бит) — адрес ячейки с базовым указателем;
- `D` (биты 32–39, 8 бит) — смещение, диапазон `0..255`;
- семантика: `addr = data_mem[C] + D`, затем
  `data_mem[addr] = data_mem[B]`.

### Бинарная операция `==` (`eq`), `A = 3`, 7 байт

- `B` (биты 4–11, 8 бит) — смещение, диапазон `0..255`;
- `C` (биты 12–25, 14 бит) — адрес второго операнда;
- `D` (биты 26–39, 14 бит) — адрес результата;
- `E` (биты 40–53, 14 бит) — адрес ячейки с базовым указателем;
- семантика: `op1 = data_mem[data_mem[E] + B]`; результат `1`, если
  `op1 == data_mem[C]`, иначе `0`, записывается в `data_mem[D]`;
- биты 54–55 всегда равны нулю.

### Контрольные значения из задания

- `load`: `A=0, B=956, C=568` → `0xC0, 0x3B, 0xE0, 0x08`;
- `read`: `A=1, B=615, C=959, D=115` →
  `0x71, 0x26, 0xFC, 0x0E, 0x73`;
- `write`: `A=9, B=302, C=84, D=113` →
  `0xE9, 0x12, 0x50, 0x01, 0x71`;
- `eq`: `A=3, B=156, C=603, D=647, E=38` →
  `0xC3, 0xB9, 0x25, 0x1C, 0x0A, 0x26, 0x00`.

Поля и значения команд проверяются при разборе, а машинный код — по
байтам: четыре команды занимают 4 + 5 + 5 + 7 = 21 байт.

### Модель памяти

- память команд — массив байтов, в который загружается двоичный файл;
- память данных — 16384 целых числа (адрес занимает 14 бит);
- память команд и память данных разделены;
- адресация с базовым указателем: `read` и `write` вычисляют адрес как
  `data_mem[ячейка] + смещение`, а `eq` — `data_mem[E] + B`;
- результат операции `==` — всегда `1` или `0`.

## Язык ассемблера

Одна строка файла — одна команда в формате CSV:

```text
command,b,c,d,e
```

- первая ячейка — мнемоника команды: `load`, `read`, `write` или `eq`;
- далее значения полей в порядке спецификации: `B`, `C`, `D`, `E`;
- неиспользуемые поля можно оставлять пустыми или не указывать;
- строка `command,b,c,d,e` может стоять заголовком, он необязателен;
- пустые строки и строки, начинающиеся с `#`, игнорируются;
- числа записываются в десятичном виде (`956`) или с префиксом `0x`.

Порядок полей по командам:

| `command` | `A` | `b` | `c` | `d` | `e` |
| :--- | :---: | :--- | :--- | :--- | :--- |
| `load` | 0 | адрес | константа | — | — |
| `read` | 1 | база | результат | смещение | — |
| `write` | 9 | источник | база | смещение | — |
| `eq` | 3 | смещение | второй операнд | результат | база |

Значения проверяются при разборе: адреса, константы и смещения должны
помещаться в свои поля, лишние заполненные поля запрещены. Сообщение об
ошибке содержит номер строки, имя поля и допустимый диапазон.

Пример программы `tests/spec_test.csv`:

```csv
command,b,c,d,e
load,956,568
read,615,959,115
write,302,84,113
eq,156,603,647,38
```

## Запуск

**Ассемблер:**

```powershell
python src/main.py <программа.csv> <машинный код.bin> [--test]
```

**Интерпретатор:**

```powershell
python src/interpreter.py <программа.bin> <дамп.xml> <start:end>
```

`start:end` — диапазон адресов памяти данных; каталог результата
создаётся автоматически. Сгенерированные файлы попадают в `output/`,
который исключён из Git.

**Скрипты запуска:** `.\tests\run.ps1` (Windows) или `./run.sh` (Linux,
macOS). Скрипты собирают все программы, выполняют их, пишут дампы в
`output/` и запускают полный набор автотестов.

## Этапы разработки

### Этап 1. Перевод программы в промежуточное представление

Создано CLI-приложение ассемблера: входной CSV-файл, выходной двоичный
файл и флаг `--test`. Язык ассемблера CSV спроектирован и описан для
всех четырёх команд. Программа разбирается в список неизменяемых
объектов `Instruction(opcode, values)`, поля проверяются по разрядности,
ошибка содержит номер строки. На ветке `stage-1` режим `--test` печатал
разобранную программу:

```text
A=0, B=956, C=568
A=1, B=615, C=959, D=115
A=9, B=302, C=84, D=113
A=3, B=156, C=603, D=647, E=38
Разобрано команд: 4
```

### Этап 2. Формирование машинного кода

Добавлены упаковка команды в машинное слово `little-endian` и обратное
декодирование. Машинный код записывается в двоичный файл, на экран
выводится число команд и размер файла, режим `--test` печатает байты:

```powershell
python src/main.py tests/spec_test.csv output/spec_test.bin --test
```

```text
0xC0, 0x3B, 0xE0, 0x08
0x71, 0x26, 0xFC, 0x0E, 0x73
0xE9, 0x12, 0x50, 0x01, 0x71
0xC3, 0xB9, 0x25, 0x1C, 0x0A, 0x26, 0x00
Ассемблировано команд: 4 -> output\spec_test.bin (21 байт)
```

Без флага `--test` печатается только итоговая строка, а код пишется в
файл. Ошибочная программа не собирается:

```text
Ошибка: Строка 3: B=20000 вне диапазона 0..16383 (адрес назначения)
```

### Этап 3. Интерпретатор и операции с памятью

Реализован CLI интерпретатора (`src/interpreter.py`), раздельная модель
памяти (`src/machine.py`), цикл выполнения и XML-дамп диапазона через
`xml.etree.ElementTree` с отступами `ET.indent`. Программа
`tests/copy_array.csv` копирует массив из восьми чисел с адресов 700–707
на 800–807:

```powershell
python src/main.py tests/copy_array.csv output/copy_array.bin
python src/interpreter.py output/copy_array.bin output/copy_array_src.xml 700:707
python src/interpreter.py output/copy_array.bin output/copy_array_dst.xml 800:807
```

```text
Ассемблировано команд: 26 -> output\copy_array.bin (120 байт)
Выполнено команд: 26
Дамп памяти [700:707] сохранён в output\copy_array_src.xml
Выполнено команд: 26
Дамп памяти [800:807] сохранён в output\copy_array_dst.xml
```

Скопированный массив совпадает с исходным (`output/copy_array_dst.xml`):

### Этап 4. Реализация арифметико-логического устройства (АЛУ)

Добавлено выполнение операции `==` (код `A=3`, 7 байт). Первый операнд
читается по адресу `data_mem[E] + B`, второй — по адресу `C`, результат
`1` или `0` записывается по адресу `D`. Программа `tests/eq_test.csv`
проверяет оба исхода при базовом указателе 500 (ячейка 40) и смещениях
0, 1 и 2:


```text
Дамп памяти [30:32] сохранён в output\eq_test.xml
```


### Этап 5. Выполнение тестовой задачи

Основная задача варианта: поэлементно применить `==` к двум векторам
длины 6 и записать результат в первый вектор. В `tests/vector_equal_6.csv`
первый вектор хранится по адресам 100–105, второй — по адресам 200–205,
ячейка 0 содержит базовый указатель первого вектора (100):

```powershell
python src/main.py tests/vector_equal_6.csv output/vector_equal_6.bin
python src/interpreter.py output/vector_equal_6.bin output/vector_equal_6.xml 100:105
```

```text
Ассемблировано команд: 19 -> output\vector_equal_6.bin (94 байт)
Выполнено команд: 19
Дамп памяти [100:105] сохранён в output\vector_equal_6.xml
```

```xml
<?xml version='1.0' encoding='utf-8'?>
<memory_dump start="100" end="105" instructions="19">
  <cell address="100">1</cell>
  <cell address="101">1</cell>
  <cell address="102">0</cell>
  <cell address="103">1</cell>
  <cell address="104">1</cell>
  <cell address="105">0</cell>
</memory_dump>
```

Первый вектор был `5, 7, 9, 11, 13, 15`, второй — `5, 7, 0, 11, 13, 0`,
поэтому третий и шестой элементы дали `0`, остальные — `1`.

Три примера программ с разными данными:

- `tests/example_1.csv` — два вектора длины 6 без совпадающих
  элементов (300–305), результат `0, 0, 0, 0, 0, 0`;
- `tests/example_2.csv` — копирование массива 600–605 в 700–705 и
  сравнение копии с оригиналом (800–805), результат
  `1, 1, 1, 1, 1, 1`;
- `tests/example_3.csv` — сравнение со сдвигом: первый вектор
  читается по смещениям 2–7, один элемент отличается (980–985),
  результат `1, 1, 1, 0, 1, 1`.

```powershell
python src/main.py tests/example_1.csv output/example_1.bin
python src/interpreter.py output/example_1.bin output/example_1.xml 300:305
```

```text
Ассемблировано команд: 19 -> output\example_1.bin (94 байт)
Выполнено команд: 19
Дамп памяти [300:305] сохранён в output\example_1.xml
```

Аналогично запускаются примеры 2 и 3 (27 и 21 команда, дампы
`output/example_2.xml` и `output/example_3.xml`).

## Проверка оформления

В репозитории есть собственный аудит оформления
(`tests/test_repository_audit.py`), написанный на стандартных модулях
`ast`, `re`, `tokenize`, `subprocess` и `pathlib`. Он проверяет:

- С1–С6: наличие `README.md`, `.gitignore`, каталогов `src` и `tests`,
  скриптов `run.sh` и `tests/run.ps1`, префикс `feat:` и число коммитов;
- Г1–Г5: отсутствие в Git архивов, бинарных файлов, служебных файлов
  Python, артефактов сборки, каталога `output/` и настроек редакторов;
- Р1: файл не длиннее 1000 строк;
- Р2: строка Python не длиннее 79 символов;
- Р6: строка скрипта или CSV не длиннее 120 символов;
- Ф1: функция не длиннее 40 строк;
- А1: не более семи аргументов у функции;
- К1: в Python нет комментариев, у модуля, класса и функции есть
  docstring;
- Ц1: цикломатическая сложность функции не больше 10;
- М1: в операциях сравнения нет числовых литералов, все пороги вынесены
  в константы;
- И1: имена соответствуют PEP 8, нет табуляций, лишних пробелов,
  импортов после кода, сравнений с `None` через `==`, изменяемых
  значений по умолчанию и `bare except`.
